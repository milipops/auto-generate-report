# 🏭 Локальный сайт производственных отчётов

## Что делает проект

Сайт на рабочем компьютере принимает свободные текстовые отчёты мастеров по
станкам, накапливает их за смену и по кнопке собирает **отчёт производства за
смену** по каждому станку: текстом, в Excel по рабочему бланку и файлом для 1С.
Разбор грязной переписки и фотографий отдаётся нейросети, но только за
структурой; часы, выпуск и балансы считает детерминированный код.

Это тот же функционал, что был в Telegram-боте: поменялся интерфейс, а расчёт,
накопитель смены, OCR и выгрузки остались прежними.

## Структура проекта

```
ForWorkTest/
├── webapp/                    # Сайт: api.py (JSON-ответы), jobs.py (фоновые
│                              # сборки), server.py (HTTP на stdlib), static/
├── config/                    # Конфигурация приложения
├── database/                  # База данных SQLite
│   ├── models.py              # Модели: User, ShiftUpload, ReportRun,
│   │                          # ProductionRecord, ProductionEvent
│   └── database.py            # Функции работы с БД
├── services/                  # Логика разбора и отчёта (про HTTP ничего не знает)
│   ├── shift_store.py         # Накопитель сообщений смены (без ИИ)
│   ├── day_pipeline.py        # Сборка дня: накопитель → ИИ → расчёт → файлы
│   ├── photo_ocr.py           # Бесплатный OCR фотографий
│   ├── excel_export.py        # Выгрузка в бланк «Отчет производства за смену»
│   └── production_parser.py   # Разбор свободных производственных отчётов
├── tests/                     # Автономные тесты на stdlib + фикстуры реальных дней
├── utils/                     # Вспомогательные утилиты
├── data/shifts/               # Накопленные смены
├── data/reports/              # Готовые файлы по датам
└── logs/                      # Логи приложения
```

## Основной функционал

1. **Сайт (`webapp/`)**
   - Приём данных без команд: текст, файл выгрузки чата, фото — с подписью
     «кто прислал». ИИ на приёме не вызывается
   - «Отчёт за дату» — один запрос к ИИ по всей смене, отчёт по станкам +
     Excel + файл для 1С; сборка живёт в фоновой задаче, страница не ждёт
   - «Готовые файлы» — скачивание без нового запроса к ИИ, «Сводный отчёт» —
     Excel по всем сменам, «Журнал» — кто что присылал и чем кончилась сборка

2. **Разбор отчётов (`services/`)**
   - Номер станка, время смены, общие и срезовые счётчики
   - Дроби (`1362 из 2030`), шпули, привязанные узлы
   - Подмены операторов, остановки/запуски машины, причины простоя словами
     мастеров
   - Предупреждения о пропусках данных («нет данных», а не выдуманная цифра)

3. **База данных**
   - SQLite + SQLAlchemy ORM, таблицы создаются на старте
   - Люди (кто прислал), журнал загрузок, журнал сборок, производственные
     записи и события
   - Хранится и агрегированная запись, и каждая строка отчёта, и исходный текст

4. **Конфигурация и логирование**
   - Pydantic Settings, переменные окружения в .env
   - Логи в файл и консоль

## 🚀 Как запустить

```bash
cd ForWorkTest
cp .env.example .env      # заполните AI_API_KEY
pip install -r requirements.txt
python main.py            # страница откроется сама
```

Проверить разбор без запуска сайта:

```bash
python tests/test_parser.py
python tests/_run_all.py  # все тесты одной строкой итога
```

## 📝 Важные замечания

- Единственный обязательный секрет — `AI_API_KEY` (ключ вашего шлюза ИИ).
  Без него отчёт соберётся упрощённо, без расчёта часов и без Excel.
- Токенов мессенджеров больше не нужно: `TELEGRAM_BOT_TOKEN` и `ADMIN_IDS` из
  `.env` убраны вместе с ботом.
- Файл `.env` включён в `.gitignore` — ключ не попадёт в репозиторий,
  используйте `.env.example` как шаблон.
- Сайт по умолчанию слушает `127.0.0.1`: доступ к переписке и счётчикам имеет
  только тот, кто за этим компьютером. `WEB_HOST=0.0.0.0` открывает его всей
  сети, пароля на сайте нет.

## 🔧 Возможные улучшения

1. Автоматическое получение отчётов из внешнего мессенджера (Яндекс 360 и т.п.)
   — требует отдельного API-доступа организации, заготовка есть.
2. Проверка на приёме («по 98 нет конечного счётчика») и автоотчёт в 19:05 —
   появится вместе с автопотоком из чата.
3. Расширение парсера под новые форматы сообщений по мере их появления.

## 🐛 Отладка

1. Проверьте, что заполнен `.env` (`AI_API_KEY`).
2. Посмотрите логи в `logs/web.log`.
3. Убедитесь, что установлены зависимости из `requirements.txt`.
4. Прогоните `python tests/_run_all.py`, чтобы проверить разбор и сайт.
